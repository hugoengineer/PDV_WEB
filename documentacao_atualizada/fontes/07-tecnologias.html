1. Visão geral da arquitetura

O PDV Web é uma API REST em camadas, executada em container Docker numa instância AWS EC2, com banco PostgreSQL. O front-end (telas do Vendedor e do Gerente) consome essa API e é a próxima etapa do projeto.

API (controllers)Rotas REST, validação de entrada, erros RFC 7807Spring Web MVC, Bean Validation, Jackson

3. Banco de dados

SGBDPostgreSQL 17
Por que PostgreSQLJá era o banco do sistema desktop; oferece CHECK, índice único parcial (um caixa aberto por operador), TIMESTAMPTZ, NUMERIC exato e bloqueio de linha confiável para vendas concorrentes.
Valores monetáriosNUMERIC(10,2) no banco e BigDecimal no Java — nunca ponto flutuante.
EsquemaVersionado pelo Flyway em src/main/resources/db/migration. Ver Diagrama ER (DOC-05) e Dicionário de Dados (DOC-06).

6. Padrões e convenções adotados

Estilo da APIREST com JSON; contrato definido na Documentação da API v2.3
Formato de erroRFC 7807 (Problem Details) com type, title, status, detail e invalid_params
AutenticaçãoJWT Bearer (RFC 7519), validade de 24 h, revogação no logout
SenhasBCrypt (fator 10)
Organização do códigoPor módulo de negócio (venda, caixa, produto…) e camadas (controller → serviço → repositório)
Decisões de arquiteturaRegistradas em ADR (docs/arquitetura/ADR-001)
Documentação de testesIEEE 829 / ISO/IEC/IEEE 29119-3
