Cenários BDD (Gherkin)

Os cenários de aceitação estão em linguagem de negócio (Gherkin em português) para que gerentes e vendedores possam validá-los sem ler código (Tutorial, seção 8). Eles não são só documentação: cada linha é executada pelo Cucumber contra a API completa e o PostgreSQL, junto com o mvnw test.

Arquivo (fonte única) Requisitos Cenários
venda_estoque.feature VAL-01, VAL-04, UC04, UC05 BDD-EST-01 (3 exemplos), BDD-EST-02
cancelamento_venda.feature VAL-02, VAL-03, UC11 BDD-CAN-01 a 03
descontos.feature UC06, UC07 BDD-DES R1 a R8 (tabela de decisão)
controle_caixa.feature VAL-05, UC02, UC03, UC15 BDD-CX-01 a 03

Passos (glue code): pdv-web-api/src/test/java/br/com/empresa/pdv/bdd/PassosPdv.java. Execução isolada: ./mvnw test -Dtest=CucumberSuite. Relatório: target/cucumber/relatorio.html (cópia da última execução em evidencias/relatorio-cucumber.html).

Como validar com as partes interessadas

  1. Ler as features com o gerente da loja e confirmar se os exemplos refletem a operação real.
  2. Cada divergência vira uma nova linha em "Exemplos" (ou um novo cenário) antes de mudar o código.
  3. Cenário com status vermelho = regra de negócio quebrada. O relatório HTML mostra em qual passo.
